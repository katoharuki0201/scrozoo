# 決定事項

## サービスとアカウント

- Web アプリケーションとして提供する。
- 投稿者アカウントの単位は動物園とする。
- 応援プランも動物園単位とし、月額500円の1種類とする。
- 動画には動物園と対象動物を紐づける。動物は絞り込みや表示分類に使い、課金単位にはしない。
- Google ログインとメールアドレス・パスワード認証に対応する。

## 動画・コメント・ギャラリー

- 無料で視聴できる動画は冒頭5秒とする。動画の最大尺は60秒を推奨値とする。
- 投稿者は Web アプリ内で動画を撮影できる。端末差に備え、ファイル選択も併設する。
- 通常コメントと投げ銭付きコメントは、ログイン済みであればプラン未加入でも投稿できる。
- 月額プラン加入者のコメントにはサポーターバッジを表示する。
- ギャラリーは誰でも閲覧でき、現地 QR 認証済みのログインユーザーは承認待ちなしで投稿できる。
- 検索対象は動物名、動物園名、動物種、タグとする。
- SNS 共有は Web Share API を優先し、非対応端末では X、LINE、Facebook、URL コピーを表示する。

## QR 認証

- アプリ内カメラで読み取れるほか、端末の標準カメラからも開ける HTTPS URL を QR に埋め込む。
- URL には動物園 ID とサーバー署名付きトークンを含める。
- 投稿者は自身の動物園用 QR コードを表示し、印刷用 PNG として保存できる。
- 発行した QR コード自体は無期限とし、失効・再生成は MVP では扱わない。
- ログイン後の検証成功時から2時間、対象動物園へのギャラリー投稿を許可する。
- 2時間の来園投稿権限では複数枚投稿できる。写真ごとにQRを再読込する必要はない。
- 位置情報は使わない。トークン署名、短時間の投稿権限、レート制限で不正利用を抑制する。

## 契約・決済モック

- 今回はStripe API、Webhook、Checkout Session作成を実装せず、共通のStripeテストPayment Linkへ遷移する。
- Payment Linkから決済完了を検証できないため、リンク遷移だけでは契約、投げ銭コメント、応援目標の金額をDBへ反映しない。
- Stripe Sandbox とテスト API キーのみを使い、実際の請求を発生させずに成功・失敗を再現する。
- 加入は即時開始、加入日の1か月後を次回更新日とする。
- 解約は自動更新の停止とし、支払済み期間の末日まで視聴権限を維持する。日割り計算と返金は行わない。
- Stripe の Webhook を署名検証し、加入、解約、投げ銭、成功・失敗の履歴を保存する。
- 80％20％の分配は事業企画上の想定とし、実際の精算・送金・本人確認は実装しない。

## プロフィールとデータ

- 全ユーザーの公開プロフィールに、ユーザー名、アイコン、自己紹介、公開ギャラリーを表示する。
- メールアドレスと課金履歴は本人のみ閲覧できる。
- 投稿者のサポーター一覧にはユーザー名とアイコンを表示し、公開プロフィールへ遷移できる。
- 退会後もコメント、お気に入り関係、ギャラリー投稿、課金履歴は保持する。表示名は「退会済みユーザー」とする。
- 退会は認証ユーザーを物理削除せず、プロフィールの退会日時を記録して全セッションを失効させる。
- パスワード再設定メールは Resend を利用する。本番では `RESEND_API_KEY` と検証済み送信元を設定する。
- 利用は13歳以上とし、18歳未満は保護者の同意を得ることを利用条件とする。今回は生年月日の入力や保護者同意フローは実装しない。

## 今回の実装対象外

- Stripe ライブモード、実際の返金、動物園への精算、本人確認
- 投稿審査、通報、運営者向けモデレーション画面
- おすすめ、フォロー、通知、分析画面
- 動画の字幕、自動再生設定、音声初期設定、再生速度変更
- サポーターチャット（個別 DM、スレッド、チャット通知を含む）
